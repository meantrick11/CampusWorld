## 1. 部署顺序

1. 上传 `jirun-domain` 公共模块。
2. 上传 3 个集合的 schema 与索引：`jr_reactions`、`jr_follows`、`jr_comments`
   （唯一索引必须生效，否则并发用例会失败）。
3. 实现并上传 `jirun-social/repository.js`。
4. 上传云对象 `jirun-social`。

## 2. 唯一关系与并发

| 编号 | 用例 | 期望结果 |
|---|---|---|
| S-01 | 同一账号从两台设备同时点赞 5 次 | `jr_reactions` 只有 1 行，计数为 1 |
| S-02 | 同一账号连续点赞 5 次 | 计数始终为 1，不出现 5 |
| S-03 | 取消点赞后重试 2 次 | 计数为 0，且不出现负数 |
| S-04 | 同一账号重复关注 3 次 | `jr_follows` 只有 1 行，关注者数为 1 |
| S-05 | 取消关注后重试 | 关注者数为 0 |
| S-06 | 检查 `jr_reactions` 与 `jr_follows` 的唯一索引是否存在 | 存在；缺失时 S-01 与 S-04 会产生重复行 |

## 3. 计数不可伪造

| 编号 | 用例 | 期望结果 |
|---|---|---|
| S-07 | 请求体中伪造 `count: 9999`、`likeCount: 9999` 后点赞 | 返回的计数以数据库实际行数为准 |
| S-08 | 客户端直接写 `jr_reactions`（add／update／remove） | 被集合权限拒绝 |
| S-09 | 客户端直接读 `jr_reactions`、`jr_follows`、`jr_comments` | 被集合权限拒绝 |
| S-10 | 未登录直接调用 `setReaction`、`submitComment`、`setFollow` | `AUTH_REQUIRED` |

## 4. 越权

| 编号 | 用例 | 期望结果 |
|---|---|---|
| S-11 | 帖子作者删除他人评论 | `FORBIDDEN`，评论未被删除 |
| S-12 | 评论作者删除自己的评论 | 成功，读者列表不再返回 |
| S-13 | 账号 B 读取账号 A 的收藏列表 | 只返回 B 自己的收藏，不返回 A 的 |
| S-14 | 账号 A 关注自己 | `INVALID_INPUT` |
| S-15 | 客户端伪造 `isReviewer: 'true'` 后删除他人评论 | 仍 `FORBIDDEN`（字符串不算授权） |

## 5. 可见性

| 编号 | 用例 | 期望结果 |
|---|---|---|
| S-16 | 对待审内容的 id 点赞 | `CONTENT_UNAVAILABLE` |
| S-17 | 内容被下架后继续点赞或收藏 | `CONTENT_UNAVAILABLE` |
| S-18 | 未通过审核的评论出现在公开列表 | 不出现 |
| S-19 | 已删除的评论出现在公开列表 | 不出现 |
| S-20 | 内容下架后其评论 | 不返回 |
| S-21 | 对取送或二手内容点赞或收藏 | `INVALID_INPUT`（这两个板块不提供该互动） |

## 6. 评论与回复

| 编号 | 用例 | 期望结果 |
|---|---|---|
| S-22 | 新评论提交后立即查公开列表 | 不出现，状态为 `pending` |
| S-23 | 审核通过后再查 | 出现 |
| S-24 | 回复一条回复 | `INVALID_INPUT`，只允许一层 |
| S-25 | 同一 `requestId` 连续提交两次 | 只产生一条评论，两次返回同一 id |
| S-26 | 回复一条已删除的评论 | `CONTENT_UNAVAILABLE` |
| S-27 | 评论列表分页包含多条主评论与回复 | 分页只对主评论生效，回复随主评论返回，不重复不遗漏 |

## 7. 分享

| 编号 | 用例 | 期望结果 |
|---|---|---|
| S-28 | 分享一条公开校园墙内容并重新访问 | 可正常查看 |
