# 暨快跑 · 前端页面与功能设计建议

版本：1.0.0｜日期：2026-09-25｜状态：本轮设计提案，未实现；新增参数为建议，不覆盖原业务待定项。

用户已确定：微信小程序优先，后续兼顾 H5；平台完全免费，用户间可自行协商费用。

## 1. 总体结构

采用手机优先布局，底部三个主入口：**广场、消息、我的**。发布是操作按钮，固定在广场右下方、安全区及底栏上方，避免与底部导航混淆。其他页面按需要展示发布入口，不全局遮挡输入区。

广场内提供“取送、二手、校园墙”三个板块切换；二手内再分“闲置、求购”。建议记住上次选择，首次默认校园墙。默认板块是本轮提案，可根据试用反馈调整。

账号、私聊、通知、举报、个人主页共用。列表卡片和发布字段按板块区分，避免用户填写无关信息。用户端与桌面管理后台分开设计。

```text
广场                     消息                   我的
├─ 取送信息              ├─ 私聊会话             ├─ 我的发布
├─ 二手：闲置 / 求购      ├─ 互动通知             ├─ 校园墙收藏 / 关注
├─ 校园墙                └─ 系统通知             ├─ 个人资料
├─ 搜索 / 筛选                                   ├─ 举报与复核记录
├─ 信息详情 → 联系发布者 → 会话                   ├─ 黑名单 / 设置
└─ 发布 → 选择类型 → 表单 → 提交结果              └─ 关于平台 / 反馈
```

## 2. 视觉方向

建议采用浅色背景、白色卡片、深色文字和青绿色主色，突出校园生活与易读性。主色用于主要按钮、选中状态和关键操作；价格用低饱和暖色，避免与违规提示混用。

建议起始色值：页面背景 `#F6F8F7`、卡片 `#FFFFFF`、主文字 `#172B26`、辅助文字 `#5F706A`、主色 `#147D64`。正文以 14～16 px 等效字号为基准，主要点击区域至少约 44 px；实际小程序适配及对比度在原型阶段检查。

首页顶部使用短说明“免费发布，直接联系”，关于页完整解释公益定位。列表不反复堆叠免责声明。所有状态同时使用文字，不能只靠颜色区分。首版建议只做浅色主题，深色主题后续按需加入。

## 3. 用户端页面与功能

| 页面 | 内容布局 | 对应功能及关键状态 |
|---|---|---|
| 广场 | 顶部品牌与搜索；板块切换；分类筛选；信息列表；发布按钮 | 下拉刷新、分页加载、保留滚动位置；加载、空列表、失败重试 |
| 取送列表 | 卡片按“起点区域 → 终点区域、物品、期望时间、报酬意向、作者、状态”排列 | 按有效状态和区域筛选；区域是选择字段，不要求读取定位 |
| 闲置列表 | 建议双列图片卡片，显示标题、价格／面议／赠送、区域和作者 | 进入详情；无图时使用统一占位；无购买按钮 |
| 求购列表 | 建议单列文字卡片，突出物品、需求数量、预算和有效状态 | 便于快速阅读要求；与闲置共用详情壳层 |
| 校园墙 | 单列内容流：头像、昵称、时间、正文摘要、图片网格或视频封面、互动栏 | 点赞、评论、收藏、分享；关注在作者区或个人页操作 |
| 搜索结果 | 搜索词、板块范围、结果列表 | 首版建议关键词加分类筛选，按新发布排序；无结果时引导修改关键词 |
| 取送详情 | 作者和状态 → 路线 → 物品／件数／时间 → 说明 → 报酬意向；底部“联系发布者” | 展示公开区域，隐藏敏感取件信息；作者看到“管理信息” |
| 二手详情 | 图片 → 价格意向 → 标题／描述／剩余数量 → 交接区域 → 作者；底部“联系发布者” | 求购详情改为预算与尚需数量；已结束时突出状态，不伪装仍有效 |
| 校园墙详情 | 完整正文和媒体 → 点赞收藏分享 → 评论及回复；作者区可关注和联系 | 作者不可单独删除他人评论；评论问题可举报 |
| 发布类型选择 | 取送需求、闲置、求购、校园墙四个入口 | 只选择信息类型，不要求先充值或认证付费 |
| 发布／编辑 | 按类型展示字段；媒体预览；底部“提交发布” | 字段校验、草稿、上传进度、提交防重复、审核结果；编辑内容重新过滤方案待确认 |
| 发布结果 | “已提交，待处理”或“已公开”等真实状态；查看我的发布 | 提交成功与公开成功分开，不用统一“发布成功”掩盖待审 |
| 消息列表 | 私聊会话为主体；顶部互动通知和系统通知入口 | 未读数量、最后消息、时间、空状态；通知不算对方私聊回复 |
| 私聊会话 | 对方信息 → 原信息卡片 → 消息列表 → 输入区 | 未回复前限一条；等待回复、正常会话、拉黑、发送失败、断线恢复 |
| 我的 | 头像昵称 → 我的发布 → 收藏关注 → 反馈／规则／设置 | 无余额、收益、提现、会员；游客展示登录入口 |
| 我的发布 | 板块与状态筛选；内容卡片；管理菜单 | 编辑、更新数量、标记进展、关闭或删除；审核与供需状态分开显示 |
| 个人资料／个人主页 | 资料编辑显示各项下次可修改时间；公开主页展示昵称头像及公开内容 | 冷却按昵称、头像分别计时；不展示私聊、举报、取件信息 |
| 举报／复核 | 对象摘要、原因、文字说明、提交结果与处理状态 | 下架原因可查看，复核可申请；不承诺自动恢复展示 |
| 关于与设置 | 公益说明、隐私与规则、反馈、黑名单、退出登录 | 黑名单解除不重置未回复前的一条消息限额 |

该表细化原 PG-01～10，并非要求每一行独立做一个页面。卡片、空状态、作者栏、媒体上传、举报表单、状态标签和确认弹窗应复用组件。

## 4. 首页与详情文字线框

以下是结构线框，不代表最终高保真视觉稿。

```text
┌──────────────────────────┐
│ 暨快跑            搜索   │
│ 免费发布，直接联系       │
│ 取送    二手    校园墙   │
│ 最新内容      分类筛选   │
├──────────────────────────┤
│ 头像  昵称       时间    │
│ 今天图书馆有人捡到……   │
│ [图片] [图片]            │
│ 点赞   评论   收藏 分享  │
├──────────────────────────┤
│ 下一条内容……            │
│                   ＋发布│
├──────────────────────────┤
│ 广场       消息    我的 │
└──────────────────────────┘
```

取送详情的固定主操作是“联系发布者”，先呈现区域路线和时间，再呈现物品与报酬。闲置详情先看图片和价格，校园墙详情先读正文。三个详情页复用作者、状态、举报和分享区，不强行使用完全相同的正文布局。

## 5. 发布字段建议

| 类型 | 必填建议 | 可选建议 | 发布后由作者维护 |
|---|---|---|---|
| 取送 | 物品类别、大小、件数、起终区域、时间要求、说明 | 报酬意向：金额／面议／无偿；物品图片 | 寻找帮助、已联系、已完成、已关闭 |
| 闲置 | 标题、分类、描述、剩余数量、价格类型 | 图片、交接区域；明确金额时填写金额 | 数量、在售／可赠送、已售出／已赠出、已下架 |
| 求购 | 标题、分类、描述、尚需数量 | 预算、参考图片、交接区域 | 求购中、已求得、已关闭 |
| 校园墙 | 文字／图片／视频至少一种有效内容 | 话题 | 编辑、删除；普通帖不强制完成状态 |

媒体参数建议起点：图片最多 9 张、校园墙单帖最多 1 段 60 秒视频、视频上传文件不超过 50 MB；这些是待确认的成本与体验参数，不是平台能力事实。后续根据真机、转码与审核能力调整。视频能力保留在 1.0.0，不能为赶进度默认为删除。

首版建议图片帖与视频帖分两种媒体形式，降低混排复杂度；此项须确认后才能作为实现要求。私聊建议先支持文字，是否支持图片另行确定，不自动继承校园墙视频能力。

## 6. 关键交互

### 登录与返回

用户访问公开分享内容可免登录。点击发布、互动、私聊时引导登录，成功后返回原操作上下文。小程序使用所选后端支持的微信登录接入；H5 后续单独配置适用登录方式，不假设可以直接复用小程序凭据流程。业务用户标识应保持独立于渠道标识，为多端账号绑定预留能力。

### 私聊申请

首次进入会话时提示“对方回复前可发送一条申请消息”；消息成功保存后显示“等待对方回复”，输入区不可继续发送。失败显示重试，不重新消耗额度。公开评论、点赞和系统通知都不解除限制。双端同时点击、断线重发和换入口时，最终由服务端按账号对判定，不依赖前端禁用按钮。

### 信息失效

已完成／售出／关闭时显示明确状态。建议新访客不再通过该信息发起新的需求联系，既有会话继续按权限访问；这一联系入口策略为设计建议。下架、删除或无权限内容返回统一不可见页面，不泄漏原内容及媒体。

### 作者管理

状态更新和内容编辑分开：标记完成不触发结算；修改正文、媒体等内容需进入审核流程。删除整帖应提示关联内容的可见性变化，不能把内容删除等同于清除举报记录。具体旧版内容展示和保留策略沿用待定项，开发前明确。

### 视频与通知

列表仅展示视频封面，点击后播放，首版不默认自动播放，控制流量与页面负担。站内消息作为可回看的通知记录；小程序离线提醒另行接入和验证，不承诺所有通知一定实时送达。

## 7. 管理后台

桌面后台采用左侧菜单加列表／详情布局，优先复用成熟后台的账号权限、表格、筛选和操作日志。移动端用户账号与后台管理员权限分离。

| 模块 | 页面和操作 | 需要保留的记录 |
|---|---|---|
| 内容管理 | 按板块、审核状态、作者、时间筛选；预览图文视频；通过／退回／下架 | 内容版本、决定、原因、操作者、时间 |
| 举报管理 | 查看对象和举报说明；关联内容版本；作出决定并通知 | 举报、处理理由及通知结果 |
| 复核管理 | 查看原决定与申请；维持或纠正处理 | 原处理、复核决定及实际恢复条件 |
| 用户管理 | 公开资料、账号状态、违规相关记录与限制操作 | 限制原因、期限及复核，不默认开放全部私聊 |
| 分类配置 | 板块分类、公开区域、发布提示和容量参数 | 修改记录；普通管理员不能改为收费模式 |
| 运行概览 | 发布量、待处理数量、错误、存储与流量使用 | 供运营排查，首版无需复杂大屏 |

## 8. 功能与开发优先级

下面是实现顺序，不是删除既定功能或改变首次上线范围的决定。

| 阶段 | 工作内容 | 完成标准 |
|---|---|---|
| A：基础与样板 | 登录、公共组件、一个板块的发布／列表／详情、上传、内容可见性、后台审核 | 一个真实内容可从提交到公开、下架，权限正确 |
| B：完整板块 | 取送、闲置、求购及校园墙表单和状态；图文视频；搜索和我的发布 | 三板块按本版规则可用，媒体失败可处理 |
| C：联系与互动 | 私聊、未回复前限一条、拉黑、站内通知；校园墙六项互动 | 多端重复请求不绕过限制，失败与断线可恢复 |
| D：治理与上线 | 举报、复核、版本处理、分享可见性、容量限制、备份与真机验证 | 业务规则可验收，运行成本有实际测量 |

无需首版引入地图轨迹、个性化推荐、交易订单或复杂多租户系统。阶段 A 的内部样板不称为已完成 1.0.0。

## 9. 核验重点

- 微信真机检查导航、软键盘、底部安全区、图片预览、视频上传／播放和分享返回路径。
- 服务端验证越权编辑、读取私聊、跨入口重复申请、重复发送、拉黑与解除后的额度。
- 检查下架后的详情、搜索结果、分享页、会话卡片及媒体访问权限。
- 使用真实媒体测量上传、存储、播放流量和审核时间，后续据此选择容量限制。
- H5 适配在后续阶段独立验证登录、分享、视频播放和消息连接，不能仅以编译成功判定可用。
