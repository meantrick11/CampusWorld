## 代码放在哪里

当前工作区是文档项目，没有应用代码。默认在当前工作区新建 `jirun/` 存放应用；保留 `1.0.0/` 作为需求来源，不修改旧版 `docs/`。执行者必须先检查目标位置是否已有代码，已有代码时复用结构，不覆盖用户文件。

如在另外一个代码仓库执行，将整个 `1.0.0/` 文件夹复制到该仓库的 `specs/1.0.0/`，并在进度记录写明 `SPEC_ROOT` 与 `APP_ROOT`。以下计划的代码路径均相对 `APP_ROOT`，不依赖当前电脑的绝对路径。

## 两类完成状态

- **本地可验证**：规则测试、页面、错误状态、模拟接口和工程结构可继续开发；模拟环境必须有清晰标识。
- **真实联调通过**：使用真实微信 AppID、开发服务空间、实际登录和真实媒体，通过真机及后台联调。没有这部分证据，不得宣称小程序已可上线。

云空间、真实凭据、管理员初始化和真机操作可能需要项目负责人配合。执行者一次列出缺失项，并继续不依赖这些输入的任务。生产资源开通、产生费用及正式发布作为最后单独执行的上线动作，计划编写不等于已经完成这些操作。

## 建议先给执行者的目标

先完成 T01～T03，交付可编译的应用骨架、纯业务规则测试、真实登录与聊天扩展验证结果。通过后按 T04～T12 继续，不重复讨论已确定的免费定位和技术主路线。若插件存在实际阻碍，提交具体错误、尝试记录及最小替代方案，不擅自删掉视频或私聊限制。
