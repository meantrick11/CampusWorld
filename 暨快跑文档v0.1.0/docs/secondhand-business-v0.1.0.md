# 暨快跑 · 二手模块业务文档

版本：0.1.0。日期：2026-09-21。状态：已确认方向与待定业务细节，尚未实现。规则编号：SH-BR；未决事项：SH-Q。

## 1. 项目背景与业务目标

### 1.1 背景与问题

用户希望二手模块支持闲置与求购，不局限于书籍或低价实物。模块连接发布者与有需求的人，提供站内联系和平台内支付。尚无本模块成交规模、频次或盈利的验证记录。

### 1.2 产品定位

**发布闲置和求购，通过站内聊天协商，由买方支付，确认收到后结算给卖方。** 求购方就是对应交易的买方；提供商品的人是卖方。平台提供信息撮合和交易流程，不提供验货、保真、赔付等额外服务保障，不做交易评价。

“类似闲鱼”是用户提出的体验方向，不直接继承外部平台的全部制度；“参照配送”指先支付、交付、确认后结算，不直接套用配送三小时代审或配送处罚。

| 问题 | 对应业务目标 |
|---|---|
| 闲置与求购信息分散 | 分开标识两种发布类型，帮助找到对应需求 |
| 描述、价格及交付理解不一致 | 协商后明确双方、商品及成交金额；具体确认方式待定 |
| 陌生人反复发送消息 | 按双方账号关系限制未获回复前只能发送一条消息 |
| 一件商品被重复购买 | 付款成功占用数量，完成计为售出，取消退款成功释放占用 |
| 卖方收款与买方收货脱节 | 买方先支付，确认收到后才触发卖方结算 |

## 2. 业务流程

### 2.1 闲置出售

发布者填写商品及数量 → 内容过滤通过后上架 → 买方查看、申请私聊并协商 → 确定交易内容 → 买方支付 → 付款成功占用一件 → 卖方交付 → 买方确认收到 → 该件计为售出并触发卖方结算。

| 环节 | 主要业务动作 | 结果 |
|---|---|---|
| 发布 | 提供商品信息，必填数量，提交过滤 | 通过后形成可购买信息 |
| 发现与联系 | 查看信息，通过单条私聊申请建立联系 | 仅聊天不扣款、不占用商品 |
| 确定交易 | 明确买卖双方、商品、金额和交付约定 | 如何发起及确认交易待 SH-Q-06 细化 |
| 支付 | 买方主动支付，确认实际支付成功 | 占用一件，可售数量减少；不立即结算给卖方 |
| 交付 | 卖方按双方约定交付 | 卖方如何声明已交付、凭证要求待定 |
| 收货与结算 | 买方确认收到 | 占用转为已售出，触发卖方结算；实际到账另行记录 |
| 数量归零 | 可售数量为零 | 自动下架、停止新购买，进行中的交易继续保留 |

初期确认的扣减单位是每次成功交易一件；是否允许一笔购买多件尚未确认，不能直接以批量库存订单作为已确认范围。

### 2.2 求购

求购者发布需求、预算和要求 → 过滤通过公开 → 供货者申请私聊 → 双方协商商品及成交金额 → 建立对应交易 → **求购方支付、供货方交付、求购方确认收到后结算给供货方**。

求购发布者是买方，不因“发布者”身份变成收款方。发布求购不等于立即扣款或向未确定的卖方预付款。求购信息仍采用求购中／已求得／已关闭；求购交易如何关联供货商品、是否复用既有商品、需求数量如何同步见 SH-Q-07。关联可售商品的交易遵循相同占用与释放规则。

### 2.3 取消、退款与举报

已确认资金与数量原则：**取消退款成功后才释放该交易占用的数量。** 退款申请或处理中不提前释放；失败时不能当作退款完成。谁可取消、何时需另一方同意、交付后的退货与退款条件尚待确定，不从配送规则直接复制。

内容举报 → 审核决定是否继续展示 → 决定下架则执行并通知原因 → 用户可申请复核。AI 为以后可尝试引入的方式。内容下架、私聊拉黑和交易取消是不同动作，不能以内容下架自动触发交易结算或退款。

未交付、描述不符、确认收到前有争议、买方迟迟不确认时，平台如何处理交易和资金仍待 SH-Q-09 明确；当前不设未经确认的自动收货、自动放款或平台赔付规则。

## 3. 服务范围与角色

### 3.1 发布范围

**支持闲置＋求购，任何可以上架的商品均可发布，不按书籍、低价或实物闲置限定。** 全新商品、商家持续售卖、虚拟商品、账号、票券和服务类商品均不因类型被预先排除，具体发布内容仍须符合上架与过滤规则。

当前暂不设置独立校园互助模块；服务类商品可在本模块发布。不同类型的数量单位、必填描述及交付方式需细化，不能把实物成色、面交位置强制用于所有商品。

### 3.2 参与角色

| 角色 | 业务职责 |
|---|---|
| 闲置发布者／卖方 | 发布商品与数量、回应咨询、按约交付、接收结算 |
| 求购发布者／买方 | 发布需求或选择商品，支付并确认收到 |
| 供货者 | 回应求购、与求购方达成约定并交付，作为卖方接收结算 |
| 平台 | 提供信息、站内联系、交易记录、数量状态、支付结算流程及内容治理 |
| 支付服务方 | 在核实可用的渠道方案下处理支付、结算和退款；具体能力待确认 |
| 审核方 | 决定被举报内容是否继续展示，下架通知原因，受理复核；AI 为后续可选方式 |

同一账号可在不同交易中担任买方或卖方。普通注册用户可以发布；实际收付款所需的渠道条件另行核实，不凭此擅自增加学生认证前置条件。

## 4. 业务规则

### 4.1 发布、范围与价格

| 编号 | 状态 | 规则 |
|---|---|---|
| SH-BR-01 | 已确认 | 支持闲置与求购，允许的商品类型见 3.1；暂不单设校园互助。 |
| SH-BR-02 | 已确认 | 任何注册用户可发布，采用昵称、头像身份，遵守 INF-BR-01～04。 |
| SH-BR-03 | 已确认数量必填／其他字段待定 | 商品上架必填数量，可售数量为零自动下架。标题、描述、分类、价格、图片等具体必填要求，以及面议、赠送、视频待定。 |
| SH-BR-04 | 待定建议 | 求购包含物品、预算、数量与要求，不强制上传实物图。必填字段与求购数量机制待定。 |
| SH-BR-05 | 已确认支付方向／报价细节待定 | 出售由买方支付；求购由求购方支付给供货方。双方成交价的确认及后续改价规则待定，展示价和求购预算不自动等于最终扣款金额。 |
| SH-BR-06 | 已确认 | 付款成功先占用一件，买方确认收到后计为售出，取消退款成功释放占用。可售数量归零自动下架并停止新购买，保留进行中交易；用户还有商品时自行决定是否重新发布，不自动补货。 |

### 4.2 发现、联系与交易

| 编号 | 状态 | 规则 |
|---|---|---|
| SH-BR-07 | 已确认 | 站内私聊按双方账号关系限制，对方未回复前总共只能发送一条消息；换商品或等待不能重置额度。支持拉黑，具体作用范围见 INF-Q-02。 |
| SH-BR-08 | 待定建议 | 支持关键词、品类、闲置／求购及有效状态筛选；价格、校区和时间筛选待定。 |
| SH-BR-09 | 待定建议 | 收藏、公开留言、关注卖家及分享入口范围待定；已公开内容通过分享链接浏览遵循免登录、互动和私聊需登录的共用规则。 |
| SH-BR-10 | 已确认 | 买方先支付，卖方交付，买方确认收到后才触发卖方结算；支付成功不等于已售出或已给卖方结算。 |
| SH-BR-16 | 已确认边界／交易发起方式待定 | 交易必须明确实际买卖双方、商品和金额；聊天、关注、已读、手动改发布状态均不能代替买方支付或收货确认。发起入口及成交约定确认方式见 SH-Q-06。 |

### 4.3 状态、治理与资金

| 编号 | 状态 | 规则 |
|---|---|---|
| SH-BR-11 | 已确认信息状态／展示细节待定 | 闲置为在售／已售出／已下架，求购为求购中／已求得／已关闭。发布状态与交易、数量、审核状态分别记录；临时全部被占用不能冒充全部成交。 |
| SH-BR-12 | 已确认保留交易／展示细节待定 | 商品下架不删除或终止进行中的交易。结束信息的历史展示、删除权限及退款释放后是否自动恢复上架待定；审核下架或作者主动下架不能因释放数量直接绕过相应限制。 |
| SH-BR-13 | 已确认 | 发布先过滤，被举报后由审核决定是否继续展示；下架通知原因，允许申请复核。AI 为后续可选方式，遵循 INF-BR-10～15。 |
| SH-BR-14 | 已确认边界／具体处理待定 | 提供平台支付与确认后结算，不提供验货、保真或赔付保障；取消退款条件与争议资金处理待细化。内容举报处理不自动产生退款或赔付。 |
| SH-BR-15 | 已确认 | 不做交易评价，不生成买卖双方交易评价或成交信用分；加入平台支付不改变这一决定。 |
| SH-BR-17 | 已确认释放时点／取消条件待定 | 取消退款成功后释放对应占用；申请中、处理中或失败不视为退款成功。是否允许单方取消、已交付后的退货退款等见 SH-Q-08。 |
| SH-BR-18 | 待定实现约束建议 | 同一支付成功事件只占用一次，同一收货确认只记售出并触发结算一次，同一退款成功只释放一次；重复通知、重复点击不能让数量或资金重复变化。确认收货与取消退款发生冲突时需核对交易状态，不能同时作为两条成功终态执行。 |

## 5. 业务状态与资金边界

### 5.1 发布与审核状态

| 对象 | 状态 | 含义 |
|---|---|---|
| 闲置 | 在售 | 允许新购买且有可售数量 |
| 闲置 | 已下架 | 停止新购买；可能因可售数量归零、作者操作或审核下架，原因分别记录 |
| 闲置 | 已售出 | 表示已成交结果；全部数量实际售出与作者手动结束信息的展示关系待细化 |
| 求购 | 求购中／已求得／已关闭 | 需求公开状态；多笔供货交易如何汇总见 SH-Q-07 |
| 内容审核 | 过滤中／未通过／通过／审核下架 | 决定内容是否公开，不替代交易状态 |

可售为零时关闭新购买，不丢失详情中的进行中交易。作者修改或删除发布信息也不能作为清除已支付交易记录的依据；具体内容删除规则待定。

### 5.2 数量变化

以同一商品发布批次的初始数量为基准，当前确认的一件交易模型为：**可售数量 = 发布数量 − 占用数量 − 已售数量**。后续修改数量、批量购买及补货另行讨论。

| 事件 | 可售 | 占用 | 已售 |
|---|---|---|---|
| 付款成功 | 减一 | 加一 | 不变 |
| 买方确认收到 | 不再扣一次 | 减一 | 加一 |
| 取消退款成功（原来仍占用） | 加一 | 减一 | 不变 |
| 退款申请／处理中／失败 | 不变 | 不变 | 不变 |

例：发布 2 件，第一笔付款后为可售 1、占用 1、已售 0；第二笔付款后为可售 0、占用 2，系统自动下架；第一笔确认收到后为可售 0、占用 1、已售 1；第二笔取消退款成功后为可售 1、占用 0、已售 1。数量释放不代表重新发布，是否自动恢复展示待定；仍有审核或作者下架限制时不能绕过。

待支付阶段如何防止多人同时购买最后一件，需在 SH-Q-10 明确；“付款成功后占用”不表示可以允许重复收款后再随意分配商品。

### 5.3 交易与资金状态

以下状态名称为业务表达，具体实现命名待设计；支付、交付、结算与退款分开记录。

| 阶段 | 已确认动作与边界 |
|---|---|
| 待支付 | 买方尚未支付成功，不因创建交易或聊天即认定付款 |
| 支付成功／待交付 | 占用一件，尚不结算给卖方 |
| 卖方交付／待确认收到 | 等待买方确认；交付记录与凭证要求待定 |
| 买方确认收到 | 占用转已售出，触发卖方结算 |
| 结算处理中／已结算 | 记录实际渠道结果；确认收到不等于资金已到账 |
| 取消退款处理中 | 保留占用，取消条件及批准方式待定 |
| 取消退款成功 | 释放原占用，关闭相应交易；实际退款结果需确认 |
| 退款或结算失败 | 记录失败并待处理，不伪装成功或重复变更数量 |
| 交易争议／长期未确认 | 资金处理、时限和解决方式待定，不默认自动放款或平台赔付 |

平台内支付的产品方向已确认，但不意味着已选定渠道或可由平台自行收取保管再转款。支付、卖方收款条件、延后结算、退款、手续费及实际到账能力，在接入真实资金前核实。本文不指定支付供应商或作出已具备能力的承诺。
