# 暨快跑 · 综合平台初期规划

日期：2026-09-21。状态：已确认平台方向；具体未决规则与首批上线组合仍待讨论，尚未实现。

业务来源：[二手模块](secondhand-business-v0.1.0.md)、[校园墙模块](wall-business-v0.1.0.md)、[信息模块共用规则](information-common-v0.1.0.md)。

## 1. 定位与目标

**让需求找到人、让人找到需求的校园信息服务平台。** 提供信息发布、站内联系，并支持有交易需求的模块在平台内支付。提供支付和确认后结算，不等于提供验货、保真、赔付等服务保障。

用户提供的校园规模约 2.4 万人是待核实背景，不等于活跃人数、交易人数或盈利规模。产品名暂沿用“暨快跑”，原宣传语用于取送；平台总宣传语和是否更名待定。

扩大场景的目的，是增加同一批用户使用平台的理由；是否能提升留存和成交仍需验证。

## 2. 当前业务范围

| 模块 | 业务闭环 | 当前边界 |
|---|---|---|
| 校园取送 | 发布、接单、交付、确认后结算 | 参照现有取送方案；其配送专属细则不直接用于其他模块 |
| 二手 | 闲置／求购、联系、买方支付、卖方交付、确认收到后结算 | 广泛允许可上架商品，必填数量；付款占用、完成计售出、取消退款成功释放，不做交易评价或额外服务保障 |
| 校园墙 | 文字／图片／视频发布、浏览、互动、举报与复核 | 点赞、评论、回复、收藏、关注、分享链接；暂不做站内转发，不提供完全匿名模式 |

**暂不设置独立校园互助模块。** 全新、商家持续售卖、虚拟商品、账号、票券、服务类商品不因类型被预先排除，具体内容须符合上架和过滤规则；服务类商品可在二手模块发布。此前校园互助作为独立模块、二手仅做书籍、平台不收款等阶段建议不再作为现行范围。

## 3. 共用能力与模块差异

1. **账号。** 二手与校园墙允许任何注册用户发布，无学生认证前置要求。昵称、头像各有一次初始修改机会，首次登录不计冷却，各自修改成功后分别冷却七天。
2. **联系。** 同一对账号在对方回复前总共只能发送一条消息，不能通过换帖子、换商品、删除会话或等待重置。支持拉黑，评论和浏览等具体作用范围待定。
3. **内容治理。** 发布先过滤，被举报后由审核决定是否继续展示；决定下架则通知原因，用户可申请复核。AI 为后续可选方式，不是首期既定依赖。
4. **分享。** 分享链接允许未登录浏览公开内容，互动和私聊需登录；下架内容、私聊及其他非公开内容不因此开放。
5. **分开记录状态。** 商品的可售数量、发布状态、内容审核及交易状态分别记录。下架不终止正在进行的交易，校园墙普通帖子不套用交易完成状态。
6. **支付。** 二手由买方付款，求购方也是买方；确认收到后结算给卖方。渠道及具体退款、争议规则另行核实，不默认具有平台担保赔付。
7. **作者权限。** 校园墙作者可管理自己的帖子，但不能删除别人的评论；整帖删除后的关联评论与举报记录处理待细化。

技术栈和实现方案未定。可考虑一个应用内划分清晰模块，共用账号、联系及治理能力，不要求微服务或通用工作流引擎。

## 4. 初期验证建议

首批上线组合待确定。试运行可缩小参与人群；二手不擅自缩回仅书籍，校园墙不擅自移除已确认的视频能力。

| 阶段 | 主要工作 | 验证依据 |
|---|---|---|
| 业务定稿 | 明确交易发起、求购供货关系、退款和未确认收货处理，细化内容治理 | 关键流程有明确角色、条件和异常出口 |
| 小范围试用 | 募集真实闲置、求购和校园内容，验证联系与治理；真实支付前核实渠道 | 有效回应、交易进展、重复使用，以及实际处理问题的能力 |
| 后续调整 | 根据需求调整商品分类和互动细节 | 有真实重复需求，开发和运营工作量可承受 |

发布量、私聊回应、支付成功、确认收到、结算成功分别统计，不把其中任一项当成其余全部完成。校园墙看有效互动，求助类可观察是否解决，不强求所有帖子有完成状态。

## 5. 页面方向与待讨论问题

用户提出广场、消息、我的三个入口。本轮只讨论业务，不设计页面。

主要未决事项：

- 二手交易如何发起并确定价格；求购如何关联供货商品及数量。
- 支付后取消、交付后退款、争议和买方长期不确认时如何处理。
- 支付渠道、收付款条件、手续费及真实结算能力。
- 商品退款释放后的恢复上架，校园墙评论管理与内容维护细节。
- 拉黑的具体作用范围、审核与复核时效、账号处罚。
- 首批上线组合、初始内容来源、名称和平台收费方式。

细节分别见 SH-Q、CW-Q、INF-Q，不把已确认的收货后结算、库存占用和昵称冷却重新列为待确认。
