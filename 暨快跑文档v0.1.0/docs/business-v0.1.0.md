## 1. 项目背景与业务目标

### 1.1 校园取送现状

校园快递、外卖等物品的取件点与学生实际所在位置存在距离。部分取件点集中在校门或驿站，用户需要专门往返才能取得物品；忙碌、不便离开、距离较远或临时搬送物品时，可能产生付费取送需求。

校园内同时存在快递站、教学楼、食堂与宿舍之间的日常出行。部分学生愿意在合适的报酬和时间条件下承接取送。需求通常是偶发的，价格接受程度随物品、距离、交付方式和时间要求变化。

现有需求及供给信息主要通过群聊、熟人联系等方式传播，发布者需要自行找到有空且愿意承接的人，并逐项沟通价格、位置和配合时间。已有信息渠道能促成交易，但订单是否仍有效、由谁承接以及最终是否完成，需要依靠双方分散确认。

### 1.2 需要解决的问题

| 问题 | 对应业务目标 |
|---|---|
| 取送需求与可接单人员的信息分散 | 集中展示可接需求，让配送者自主选择 |
| 对物品、起终点、价格和时间理解不一致 | 在接单前明确固定 A→B、物品范围、报酬和时限 |
| 动态码等取件信息需要临时配合 | 提前同步预计取件时间，提供请求通知和联系渠道 |
| 变更、取消及交付过程难以追溯 | 保留双方约定、业务状态和必要交付记录 |
| 报酬与交付结果需要对应 | 下单支付、按约完成后结算，取消与异常按规则处理 |

### 1.3 产品定位

暨快跑整体定位为校园综合信息服务平台，当前范围为校园取送、二手（闲置＋求购）和校园墙，暂不单设校园互助；新增模块的已确认与待定规则见各自业务文档。校园取送模块提供信息撮合与履约服务：用户发布需求并自主报价，配送者根据路线、报酬、时间及自身能力决定接单；接单后按约定完成交付。

“顺路”是业务出发点，是否值得接单由配送者自行判断，平台不核验原有行程。服务涵盖快递代取、外卖取送和适合承接的物品搬送，核心交付单位是明确的 A→B 订单。

### 1.4 已有业务信号

已有两次真实付费代取记录，以及发布消息不到二十分钟出现电竞椅搬送需求、双方协商至十元接单的记录。电竞椅案例尚未补充交付及收款结果。这些记录说明存在具体需求和议价行为，尚不足以认定稳定订单规模、市场价格或盈利能力。

详细事实、报价过程与结果状态见[需求来源与真实案例](requirements-v0.1.0.md#evidence)。

## 2. 业务流程

可编辑图源：[三页 draw.io](diagrams/business-v0.1.0.drawio)。图示概括主要路径，具体条件以 BR 规则为准。

### 2.1 正常交易

发布并支付 → 自主接单 → 按需配合取件 → 实际取件 → 按约交付 → 配送者点已送达 → 用户确认／特殊情况等待三小时后平台代审通过 → 结算。

| 环节 | 主要业务动作 | 结果 |
|---|---|---|
| 发布与支付 | 用户确定物品、A／B 点、报价、时限和交付方式，了解服务边界与异常处理约定，确认后支付 | 订单进入待接单 |
| 自主接单 | 配送者核对服务条件、履约责任及异常处理约定；需即时配合时选择预计取件区间并同步用户，确认承接 | 订单由该配送者承接 |
| 取件配合 | 配送者按约到站，按需请求动态码或验证信息并联系用户 | 获得取件所需信息 |
| 实际取件 | 核对并取得约定物品 | 进入配送阶段 |
| 按约交付 | 送到用户指定位置后配送者点“已送达”；特殊情况附位置照片 | 正常待用户确认；照片订单入队等待三小时 |
| 确认与结算 | 用户确认，或特殊照片满三小时未确认后经后台代审通过 | 触发结算；用户确认后退出代审队列，不重复结算 |

正常流程统一为：按约送到 → 配送者点“已送达” → 用户确认 → 结算。特殊情况点“已送达”并附照片，先进入待审队列等待用户确认；三小时内用户确认就结算并退出队列，三小时后仍未确认才人工代审，审核通过直接结算。三小时是用户确认等待期，不是自动放款倒计时；不再采用先审核再等三小时的旧规则。

![目标主流程](diagrams/01-main.svg)

### 2.2 取件配合

需要配合才选择预计到站的五分钟区间（如 18:30～18:35），接单成功时同步通知用户。用户在自己选择的服务时段准备配合，首版不额外增加一轮取件时间审批；预计时间变化先沟通。不需配合则直接按约取件，不强制索码或验证。五分钟到站区间、三分钟失联等待与特殊送达提交后三小时用户确认等待是不同时间概念，不能混用。

![取件配合流程](diagrams/02-pickup.svg)

### 2.3 异常处理

发现问题 → 告知对方 → 尝试协商 → 能继续返回原流程；不能继续按未取件／已取件处理。BR-27 的取件前失联允许自行终止；已取件必须先明确物品交接。更复杂的争议仍有未定规则，不能假设人工客服已经可用。

物品损坏、丢失或交付争议采用统一分支：提交异常并留存记录 → 通知双方、暂停争议订单结算 → 优先协商 → 分别确认物品交接、配送费处理和物品损失赔偿 → 按有效处理结果更新订单。反馈本身不等于责任已查明；无法协商时由平台提供必要协助及外部解决途径，资金处理期限与最终结束条件仍待 Q-10 明确。

## 3. 服务范围与角色

### 3.1 服务范围

当前已细化的取送首版围绕快递、外卖及适合承接的物品搬送。二手和校园墙已纳入综合平台规划，二手范围不限书籍，暂不单设校园互助；首批上线组合待定，不能将本文取送首版等同于整个平台首版。本文 BR 规则和流程图仅适用于取送，不直接套用于商品交易或内容发布。不增加专送调度、实时轨迹、复杂信用体系或完整人工客服系统。

校园所有区域开放，不按用户所在区域限制订单浏览和发布。所有人可浏览可接订单公开信息，注册用户可发布，取得配送资格后才能接单；公开信息不含电话、取件码和精确寝室号。区域开放不代表保证楼栋可进入或订单必有人接。用户侧同步等待接单、已接单／待取件、配送中、待确认等业务进度，不依赖精确地图定位。

物品选择小／中／大／特大并附简短描述，配送者自行判断携带能力。特大档位不自动包含洗衣机等原排除物品；分类文案待补。代取可行、部分需动态码；宿舍通行权限待核实，不能默认所有楼栋都能进入。

### 3.2 参与角色

| 角色 | 业务职责 |
|---|---|
| 需求用户 | 注册后下单支付，提供真实条件，按需配合取件，确认交付 |
| 配送者 | 提交学生证等资料申请资格，自主选单、可接多单，接单后按约履行 |
| 平台 | 提供信息、权限、通知、订单和资金状态记录；实现已明确的规则，不承诺替补配送 |
| 驿站／楼栋管理方 | 决定具体代取、验证与进入条件 |
| 支付服务方 | 预付、补款、退款、结算能力和时效尚需核实 |

## 4. 业务规则

规则按发布、接单、协商及结算归组。

### 4.1 发布、范围和价格

| 编号 | 状态 | 规则 |
|---|---|---|
| <a id="br-01"></a>BR-01 | 已确认 | 用户发布需求，填写物品类别、大小、件数、取送位置和时间要求。 |
| <a id="br-02"></a>BR-02 | 已确认方向／价格暂定 | 平台提供按件参考价：小件 3 元、中件 5 元、大件 10 元、特大件 15 元；仅用于帮助用户报价，不是强制最低价或保证成交价。用户发布前可自主填写高于或低于参考价的报酬，配送者自行决定是否接受。替代此前平台规定起步门槛的设想；发布支付后的价格变更仍遵守 BR-23～26。 |
| <a id="br-03"></a>BR-03 | 已确认＋待定 | 通常一件一单；同一 A 点、同一 B 点的多件可捆绑为一个订单，整单接取和交付，如三个小件。A 或 B 不同则分别发单。按件计价并显示总价；不同规格组合的单价填写方式待定。未经双方确认的部分交付不能按整单成功结算；双方协商减件后，以 BR-26 确认的新范围判断整单是否完成。 |
| <a id="br-06"></a>BR-06 | 已确认＋待定 | 无人接单时用户可加价，到接单截止时间关闭订单并通知用户；加价提醒策略后续确定。 |
| <a id="br-07"></a>BR-07 | 已确认 | 默认接单截止为最迟送达前 15 分钟，用户可调整。初期不按实际距离计算余量，配送者自行判断能否履约。 |
| <a id="br-24"></a>BR-24 | 已确认 | 未接单时用户可在原单上调或下调配送费，保留编号和调价记录，不自动延期。改价处理期间暂不可接；加价完成补款后展示新价，降价记录应退差额及实际退款进度，不把发起退款视为到账。改价失败保持原有效价格，结果不明先核实。若接单先成功，不能直接改价，转入 BR-23 的双方变更请求。关闭后的迟到支付结果不恢复可接，核对并退回多收款。 |
| <a id="br-29"></a>BR-29 | 已确认 | 未接单改 A／B 点、件数或大小，初期采用取消退款后重下单；联系方式和必要备注可修改并留记录，但不得借备注改变核心服务条件。可显式调整时间，须保留有效的截止与送达关系，已截止订单不得直接恢复可接。此规则不影响接单后的双方协商变更。 |

### 4.2 接单、身份与取件配合

| 编号 | 状态 | 规则 |
|---|---|---|
| <a id="br-04"></a>BR-04 | 已确认 | 配送者确认有能力按要求送达后接单；可同时接多个订单。并发件数或订单上限待定。 |
| <a id="br-05"></a>BR-05 | 已确认 | 接单后订单退出可接单大厅，由该配送者履约；这不是取消或删除订单。 |
| <a id="br-10"></a>BR-10 | 已确认 | 完整接单后才可查看对应取件信息；不得在大厅公开取件码。 |
| <a id="br-11"></a>BR-11 | 已确认＋待核实 | 现有取件场景中存在用户提供三分钟有效身份码的要求。有效期、授权范围及代取接受方式需现场核实，不能当作所有驿站的通用规则。 |
| <a id="br-20"></a>BR-20 | 已确认 | 对需要用户即时配合的订单，配送者在确认接单前填写预计到达取件点的五分钟区间，接单成功时同步通知用户。用户在自己选择的服务时段准备配合，不再强制额外确认该区间；通知不等于已读。预计时间变化先沟通，不将提前到站等同于用户失约。不需配合则不强制区间、索码或验证步骤，依据实际取件方式判断。 |
| <a id="br-22"></a>BR-22 | 已确认／材料细节待定 | 注册用户可下单；配送资格提交学生身份等基本资料，由平台后台审核通过后才能接单，不因上传齐全自动通过。具体材料、审核人员及资格审核时效待细化，与送达代审分别管理。 |
| <a id="br-25"></a>BR-25 | 已确认 | 接单后配送者可获取本单用户电话号码，履约过程中双方可持续通过交流频道和电话协商。到取件点可点击“索要动态码”等操作通知用户；等待较久可电话联系。通知或拨号不等于用户已读、已接听或同意变更；只记录实际可确认的业务事件。 |
| <a id="br-27"></a>BR-27 | 已确认 | 需要用户即时提供动态码、验证等信息时，配送者按已告知的预计取件安排到站，发起请求并尝试联系失败后等待三分钟；用户仍未配合且实际尚未取件，配送者可自行终止交易。记录请求、联系尝试、计时及关闭原因，通知用户并原路退款，不支付配送报酬。该路径不要求对方再次同意或人工客服审核；符合条件时记为用户未及时配合，不算配送者主动失约。用户及时提供有效信息后继续履约，不能再以原失联原因终止。 |

### 4.3 协商、变更和退出

| 编号 | 状态 | 规则 |
|---|---|---|
| <a id="br-08"></a>BR-08 | 已确认＋待定 | 未接单时用户可直接取消并原路退款。接单后一般由任一方申请、另一方明确同意后取消；正常未取件协商取消后原路退款，不支付配送报酬。BR-27 是明确例外：需要用户配合取件但联系失败、等待满三分钟仍未取件时，配送者可自行终止，无需再等用户同意或人工客服批准。已取件须先解决交接，不适用此例外。取消是关闭订单，不删除历史。 |
| <a id="br-09"></a>BR-09 | 已确认／部分执行细则待定 | 接单即须履约。最终双方约定送达截止后给予 15 分钟宽限，结束时仍无用户接收确认或有效代审结果，且无宽限结束前提交的待确认送达记录，自动限制接新单 15 天；其他功能不受影响。及时提交的送达记录先待用户确认；特殊照片满三小时后由后台代审核对实际送达时间，不因后台审核耗时直接处罚。偷吃外卖、私自占有包裹等行为经核实后纳入违规；超时或单方投诉不能直接证明偷拿。累计两次有效违规直接封号，正常订单不清零；支持申诉工单，后台复核纠错。限制从触发时起记录起止时间，不自动取消、退款或结束物品交接。合规取消、BR-27 终止不直接计为违规。计数、待审核衔接见 5.3，封号具体范围及申诉时效待 Q-11。 |
| <a id="br-14"></a>BR-14 | 已确认 | 接单后保留服务范围、件数与报价快照；变更须双方确认，不能单方修改履约条件。电话协商可用于沟通，影响物品、金额、时间或交付方式的结果需回写订单并留下双方确认记录。 |
| <a id="br-15"></a>BR-15 | 已确认／衔接待细化 | 超过最终双方约定的最迟送达时间，保留迟到记录；再经 15 分钟宽限仍不满足 BR-09 的确认或及时提交送达记录条件时，自动限制接新单；订单不因限制直接取消、退款或重新派单。预计迟到应先沟通，以双方同意的变更请求更新时限并保留原约定。用户最终收货并确认仍可结算，但不自动撤销已经产生的限制；配送者可通过申诉工单申请复核。不设自动罚款或迟到赔付。 |
| <a id="br-16"></a>BR-16 | 已确认 | 全程先双方沟通，能继续则确认必要变更并履约；不能继续优先按规则取消、退款后由用户决定重新发布，不引入在线客服系统。未取件按 BR-08／27，已取件须先明确物品交接及费用，取件状态不明不得直接重发。协商不成不等于对方同意取消；不满足已有退出条件时保留异常记录和待处理事项，不虚构自动关单。后台承担资格审核、送达照片审核和申诉工单复核，不扩展成客服调度。 |
| <a id="br-17"></a>BR-17 | 已确认 | 接单后允许提出交付变更，双方明确同意后生效。同一目的地当面交付改为放门口等轻微变更通常沿用原价；明显增加负担时另行协商价格及时间。未达成一致不单方更改原约定。指定位置放置需要留存交付照片。 |
| <a id="br-23"></a>BR-23 | 已确认 | 接单后任一方可在沟通后发起价格或服务条件变更请求，另一方明确同意后才能形成新约定；未同意不覆盖原约定，沉默不视为同意。增加报酬由用户完成补款，减少报酬记录差额退款；双方同意和资金实际处理分别记录。不得单方加价、减价或扣款；金额以双方确认且完成相应补款的有效约定为准，退款进度单独展示。 |
| <a id="br-26"></a>BR-26 | 已确认需求／首版基础操作 | 部分取件等异常先沟通，再由任一方发起件数、报酬或相关信息变更请求，对方同意后按新约定履约。用户可操作改单，不代表可单方改变已接单条件。例如三件六元改为两件四元，双方确认后退回两元差额，两件全部送达后按四元结算。保留新旧约定、双方确认及差额处理结果，具体字段与交互待细化。 |
| <a id="br-28"></a>BR-28 | 已确认 | 下单可自愿指定联系不上时的备用交付位置和方式；配送者按明确授权放置、拍照并通知。无授权不得擅自放置；需协商其他交接或平台处理。不假定驿站可接收退回，也不自动要求配送者承担返回 A 点的新行程。 |

### 4.4 完成、结算、责任和记录

| 编号 | 状态 | 规则 |
|---|---|---|
| <a id="br-12"></a>BR-12 | 已确认／支付能力待核实 | 用户下单支付后订单可接取。整单按约完成后，配送者先点击“已送达”，用户确认接收则触发结算；特殊照片订单按 BR-19 等待用户确认，三小时后仍未确认才由平台代审，通过后结算。没有用户确认或有效代审通过，不因超时直接支付报酬；实际到账时效依支付方案。 |
| <a id="br-13"></a>BR-13 | 已确认边界／条款待审查 | 平台提供信息撮合、订单服务、异常反馈及必要协商协助，不提供额外物品保险或兜底赔付承诺，不保证每单不发生意外。各方依法承担相应责任；平台自身依法应承担的责任不因免责声明或收费较低而免除。该边界须在下单及接单前明确告知。 |
| <a id="br-18"></a>BR-18 | 已确认 | 配送者自行判断接单是否值得、能否完成，平台不验证是否真正顺路。接单后须履约；在用户约定时间内按约定位置和方式完成正确物品的交付，即为履约成功，结算仍按交付确认规则办理。 |
| <a id="br-19"></a>BR-19 | 已确认／代审细节待定 | 正常流程为实际送到用户指定位置 → 配送者点击“已送达” → 用户确认接收 → 立即触发结算，不强制拍照。联系不上用户等特殊情况，配送者点击“已送达”时须附位置照片及说明，进入人工代审队列的等待阶段；从本次已送达提交成功时刻起计三小时。三小时内用户确认且无未解决异议，直接结算并退出代审队列；满三小时仍未确认才转后台人工代审，通过后直接触发结算，不再另等三小时，不因到期自动放款。待代审或代审处理中用户确认且无未解决异议，同样终止代审并结算，防止重复付款。用户可在等待及代审期间提出异议，暂停结算并走异常流程；不通过则不结算并说明原因。重复点击不重置计时，补件处理见 Q-08。未附照片的正常送达不自动套用照片代审。 |
| <a id="br-21"></a>BR-21 | 已确认 | 双方有可协商的交流频道；平台保留订单全流程业务记录，用户可查看自己的进行中、已完成、已取消等历史。取消申请、双方同意、变更、交付及支付退款结算结果均需可追溯，不因订单结束而删除。 |
| <a id="br-30"></a>BR-30 | 已确认要求／展示方案见需求文档 | 下单支付前及确认接单前，分别向用户和配送者清晰说明服务内容、各自配合或履约义务、取消与确认结算规则、无额外兜底保障及争议处理方式。不得仅以隐蔽小字或笼统同意代替重要提示；告知不等于转移全部责任，具体条款须结合实际模式审查。 |
| <a id="br-31"></a>BR-31 | 已确认原则 | 配送费与物品损失分开处理。配送费按既定退出规则、双方确认的处理方案或其他有效依据退款或结算；物品损失另行确认事实、责任和赔偿。退款不等于物品赔偿，不自动消灭其他请求。未取件按 BR-08／27 处理，已取件先明确物品交接，不能仅退款就视为全部争议解决。 |
| <a id="br-32"></a>BR-32 | 已确认原则／处理细则待定 | 双方可报告异常、提供说明及必要凭证，优先协商；存在交付异议时暂停结算，不因单方投诉自动退款、认定盗窃或要求某方赔偿。平台保留记录、提供必要协助并记录处理结果，不承诺所有事实均能查清或承担全部损失。平台协助范围不等于放弃其依法应尽的义务。 |
| <a id="br-33"></a>BR-33 | 已确认边界／资金规则待定 | 协商无果时，可提供投诉、调解、依法诉讼等途径；疑似盗窃、诈骗或人身危险等情况可提示向警方求助，普通配送争议不默认导向报警。外部求助不自动关闭订单、不等于责任认定。争议资金不得任意划付或无限期悬置，具体处理期限、依据及申诉方式须在真实预付上线前确定，不在当前规则中虚构自动终局结果。 |

## 5. 业务状态与资金边界

| 业务阶段 | 下一步 |
|---|---|
| 待支付 | 支付成功才进入待接单；失败不成为可接单订单 |
| 待接单 | 接单、原单上调或下调配送费、取消或截止关闭；改价处理期间暂不可接 |
| 已接单／待取件 | 取得物品后配送；双方协商取消，或符合 BR-27 自行终止 |
| 已取件／配送中 | 按约交付；异常时先处理物品，不能套用未取件退出 |
| 已实际交付 | 配送者点击“已送达”；正常不强制照片，特殊情况附位置照片 |
| 特殊送达／等待用户确认 | 从“已送达”提交成功起等三小时；入队但尚不代审，用户确认即结算并出队 |
| 待确认／待代审 | 正常送达等用户确认；特殊照片满三小时未确认才代审，通过即结算；有异议转异常 |
| 已完成／已关闭 | 保留历史，分别跟踪结算或退款结果 |

超时、取消申请、价格更新及争议须保留原履约进度。业务关闭不等于退款到账；用户确认后立即触发结算，实际到账时效待支付方案核实。

资金主线：下单支付 → 待结算 → 结算处理中 → 已结算；退款单独记录处理中、成功或失败。加价差额和后续减件退款都需可追溯。具体账户结构待支付方案确定。

### 5.1 异常订单的处理边界

| 情况 | 配送费处理 | 物品及赔偿处理 |
|---|---|---|
| 未取件，满足已明确取消或终止条件 | 按 BR-08／27 原路退款 | 未接收物品，不新增交接动作 |
| 已取件，双方同意停止 | 按双方确认且符合适用规则的方案处理 | 先明确包裹交接；不能擅自遗留物品 |
| 双方认可损坏事实及配送费退款方案 | 按确认结果退款，不自动支付成功配送报酬 | 另行协商损失赔偿；不由平台默认垫付 |
| 一方称送达，另一方称未收到 | 暂停结算，不仅凭投诉立即退款 | 保留双方说明和凭证，协商或按合法有效处理依据解决 |
| 配送费已处理，物品赔偿仍有争议 | 显示配送费实际处理结果 | 物品争议单独保留，不能显示为“全部争议已解决” |

接收反馈、提示外部渠道和记录处理结果属于基础协助，不等于已建立全天候客服、保险或自动责任认定能力。

### 5.2 沟通、留证与配送者审核

面向双方的文案见[下单与接单说明（草案）](service-notices-v0.1.0.md)。正常当面交付不要求照片；无法当面交付而经授权放置时，照片须能辨认本单物品及具体位置，如寝室门牌、楼栋／楼层标识或与放置点明确对应的固定标识物，仅拍附近地标不充分。详见[放置照片提示](service-notices-v0.1.0.md#photo)。配送资格由平台后台审核，通过后才可接单，见[审核建议](service-notices-v0.1.0.md#review)。

全程优先双方沟通：发现问题 → 联系并说明 → 确认变更或按规则取消 → 退款后用户决定是否重新发布；已取件先明确物品交接，不引入在线客服系统。后台保留资格、送达照片审核和申诉工单处理。提交交付异议仍应及时暂停结算，不以先完成协商作为异议受理条件。

交付优先遵守用户约定；无法按原位置交付先协商，不仅凭照片擅自改放门口。正常交付也由配送者先点击“已送达”，再由用户确认。特殊情况下在该操作中附物品及具体位置照片，保留联系说明；三小时从提交成功起算，期间用户确认则结算并退出代审队列，超过三小时未确认才由后台代审，通过后直接结算。审核不通过或存在未解决异议不结算。照片不能代替授权，不单独保证事实已查清。

丢件时平台协助整理订单、时间、位置及沟通记录，联系学校保卫部门或监控管理方，协助当事人按程序申请查阅相关监控；不承诺平台有直接调取权限或必然取得录像。学校封闭、有监控不代替送达证据。查阅条件参见[《公共安全视频图像信息系统管理条例》第二十一条](legal-references.md#video)。

配送者审核资料建议（待确认）：姓名、学校／校区、学号、经验证的联系电话，以及可核对上述信息的学生身份证明；优先现场核验或学校可用的验证方式，材料遮盖无关字段。初期不建议额外收集身份证正反面、家庭住址或家人联系方式。具体材料、审核人、保存期限仍按 Q-11／Q-13 确定；最小必要原则参见[《个人信息保护法》第六条](legal-references.md#personal-information)。

审核用于确认身份、联系和追溯，不能保证一定履约。建议将校内身份与账号关联，限制期间不能仅更换手机号重新取得接单资格。跑单不提供平台额外兜底赔付，但仍保留异常协助、订单资金处理及各方应承担的责任，不能写成跑单后平台不再处理。

代审不通过不支付报酬；缺少位置证据与查实偷吃、私自占有物品分别记录，不能把证据不足直接定性为偷拿。已核实违规按 BR-09 处理，配送费和物品交接另按异常结果处理。

### 5.3 宽限、照片审核与累计违规

本轮确认：送达截止后宽限 15 分钟；违规累计两次封号，正常完成订单不清零。宽限只用于接单限制判定，不抹去原送达时限及迟到记录。

| 时点／条件 | 处理 |
|---|---|
| 最终约定送达截止至其后 15 分钟 | 给用户确认或配送者点击已送达（特殊情况附照片）的时间；不因未点击确认立即限制 |
| 宽限结束时用户已确认且无未解决交付异议 | 不因确认晚于原截止自动限制；另记实际迟到情况 |
| 宽限结束前已提交“已送达”（特殊情况附照片） | 先待用户确认或代审判定，不因用户未点击或三小时等待及人工耗时直接处罚；单方报送不证明实际交付 |
| 宽限结束既无用户确认或有效代审结果，也无及时提交的待确认送达记录 | 自动触发 15 天接单限制，保留申诉入口；其他功能不受影响 |
| 三小时后代审通过，证据支持宽限内按约送达 | 不因确认或审核晚于宽限结束认定违规；代审通过直接结算，不再额外等待 |
| 照片不支持有效交付或实际送达超过宽限 | 后台按实际记录判断并记录原因，不靠照片提交动作永久免除超时判断；支持申诉 |
| 用户提出交付异议 | 暂停结算并进入异常，不仅凭异议认定配送者违规；是否已送达需结合记录判断 |

计数以同一订单的一次有效违规为单位，同一单的超时、偷吃或私自占有等不重复累计。首次限制接单 15 天，累计第二次有效违规封号；申诉成立须撤销对应记录并重算限制与累计次数，避免已撤销记录导致封号。实际送达时间、上传时间、审核通过时间、用户确认时间分别记录；处罚计数与配送费、物品交接分开处理。

执行衔接：及时提交的送达记录先待确认／核实，不能把正常无照片交付因用户未确认直接判为超时；正常未确认且无照片的催确认、证据核实方式仍待 Q-08。后台代审在特殊送达提交满三小时后开始，处理时限、补件和申诉细节待定，不默认审核通过。
